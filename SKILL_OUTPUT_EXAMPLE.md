## 2. GitHub PR Description

### Example PR Title
```
Security: Fix 9 Vulnerabilities
```

### Example PR Body

```markdown
## Security Vulnerabilities Fixed

Automatically scanned and fixed **9** security vulnerabilities in the codebase.

### SQL Injection (3 instance(s))
Files: src/api.js, src/auth.js, src/database.js
Description: Unparameterized SQL query vulnerable to injection attacks

### XSS Vulnerability (3 instance(s))
Files: src/email.js, src/fileupload.js, src/logger.js
Description: innerHTML usage allows XSS attacks via untrusted content

### Hardcoded Secrets (1 instance(s))
Files: src/database.js
Description: API keys or passwords hardcoded in source code

## Actions Taken

- [x] Scanned all source files for security vulnerabilities
- [x] Applied security fixes automatically
- [x] Parameterized SQL queries to prevent injection
- [x] Changed innerHTML to textContent for XSS prevention
- [x] Moved hardcoded secrets to environment variables
- [x] Added authentication checks where missing

## Testing Required

- [ ] Verify all API endpoints still function correctly
- [ ] Test authentication flows
- [ ] Run security tests to confirm fixes
- [ ] Check for any broken functionality

## Security Best Practices Applied

1. **SQL Injection Prevention**: Using parameterized queries
2. **XSS Prevention**: Using textContent instead of innerHTML
3. **Secret Management**: Storing sensitive data in environment variables
4. **Authentication**: Added middleware to protect endpoints
```

### How Each Issue Was Fixed:

**SQL Injection (CRITICAL)**
- Issue: Unparameterized SQL queries vulnerable to injection attacks
- Fix: Added parameter placeholders and moved to parameterized query syntax
- Impact: Prevents unauthorized database access and data breaches

**XSS Vulnerabilities (HIGH)**
- Issue: innerHTML usage allows injection of malicious scripts
- Fix: Changed to textContent which escapes all content
- Impact: Prevents stored and reflected XSS attacks

**Hardcoded Secrets (CRITICAL)**
- Issue: API keys and passwords exposed in source code
- Fix: Moved to environment variables using process.env
- Impact: Prevents credential exposure and unauthorized API access

**Missing Authentication (HIGH)**
- Issue: Sensitive endpoints lack authentication checks
- Fix: Added authentication middleware to protected routes
- Impact: Prevents unauthorized access to admin functions

## 4. Slack Notification

### Slack Message Format

When SLACK_WEBHOOK_URL is configured, you'll receive a formatted Slack message like this:

```
┌─────────────────────────────────────────┐
│ Security: Vulnerabilities Fixed         │
│           and Patched                   │
├─────────────────────────────────────────┤
│ Issues Found and Fixed:                 │
│                                         │
│ 🚨 SQL Injection: 3 instance(s)        │
│ ⚠️ XSS Vulnerability: 3 instance(s)    │
│ 🚨 Hardcoded Secrets: 1 instance(s)    │
│                                         │
├─────────────────────────────────────────┤
│ Total Issues: 9                         │
├─────────────────────────────────────────┤
│           [Review PR Button]            │
│  Opens: https://github.com/.../pull/4  │
└─────────────────────────────────────────┘
```

**Features:**
- Severity indicators (🚨 CRITICAL, ⚠️ HIGH)
- Issue counts grouped by type
- Direct clickable link to GitHub PR
- Color-coded message (red for critical)

## 5. What Happens If Slack Webhook Is Missing

If `SLACK_WEBHOOK_URL` is not configured in `.env`:

```
Creating branch and pushing code...
  Created branch: security/fix-vulnerabilities-1785407796
  Staged 6 files
  Committed changes
  Pushed to GitHub
  PR created: https://github.com/hamza31-source/my-app/pull/4

Adding detailed comment to PR...
  PR comment added successfully!

Sending Slack notification...
  Slack webhook not configured (SLACK_WEBHOOK_URL not in .env)
  Skipping Slack notification

Security workflow completed!
```

**Result:** No error - skill continues and completes successfully!

## Summary

✅ **Scan**: Detects all security vulnerabilities
✅ **Fix**: Applies automatic security fixes  
✅ **Branch**: Creates new feature branch
✅ **Commit**: Stages and commits all changes
✅ **Push**: Pushes to GitHub
✅ **PR**: Creates pull request with detailed description
✅ **PR Comment**: Adds comprehensive explanation of each issue and fix
✅ **Slack**: Sends notification (if webhook configured, skips otherwise)

**No manual steps required!**
